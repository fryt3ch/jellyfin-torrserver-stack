# 🎬 Jellyfin + TorrServer (optional VPN)

**A ready-to-run Docker Compose stack that pairs Jellyfin with TorrServer, with an optional Gluetun VPN profile for regions with strict torrenting laws.**

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

- 🐳 **One command** to start Jellyfin + TorrServer.
- 🔌 **Drop-in** with the [TorrServer STRM Manager](https://github.com/fryt3ch/Jellyfin-TorrServerStrm-Plugin) Jellyfin plugin.
- 🛡️ **Optional VPN** (Gluetun, WireGuard — including Cloudflare WARP) that routes TorrServer traffic only.
- ⚙️ **Configurable** paths, UID/GID, timezone, and bind address via `.env`.

---

## 📋 Requirements

- Docker Engine + **Docker Compose v2.24+** (the VPN overlay uses the `!reset` tag).
- A downloads/media path that Jellyfin can read.
- Optional: the [TorrServer STRM Manager](https://github.com/fryt3ch/Jellyfin-TorrServerStrm-Plugin) plugin to import magnets as `.strm` files.

---

## 🚀 Quick start (no VPN)

```bash
# 1. Create the shared network used by Jellyfin and TorrServer
docker network create nginx-net

# 2. Configure
cp .env.example .env
# edit .env: PUID/PGID, TZ, DOWNLOADS_PATH, ...

# 3. Start
docker compose up -d
```

Jellyfin is reachable from other containers on `nginx-net` as `http://jellyfin:8096`.
TorrServer is reachable as `http://torrserver:8090`.

If you are **not** behind a reverse proxy and want direct access, uncomment the
`ports` entries in `docker-compose.yml` (or use `docker-compose.override.example.yml`).

## 🛡️ Enable the VPN profile (strict regions)

The VPN overlay moves TorrServer into a Gluetun network namespace so **all**
TorrServer traffic goes through the VPN. Jellyfin is unaffected and still
reaches TorrServer as `http://torrserver:8090`.

1. Fill in the `WIREGUARD_*` values in `.env` (see below).
2. Start with the `vpn` profile:

```bash
docker compose --profile vpn \
  -f docker-compose.yml -f docker-compose.vpn.yml up -d
```

### WireGuard values

Gluetun's `custom` provider needs:

| Variable | Meaning |
| --- | --- |
| `WIREGUARD_PRIVATE_KEY` | Client private key |
| `WIREGUARD_ADDRESSES` | Client address, e.g. `10.2.0.2/32` |
| `WIREGUARD_PUBLIC_KEY` | Server public key |
| `WIREGUARD_ENDPOINT_IP` | Server endpoint IP/host |
| `WIREGUARD_ENDPOINT_PORT` | Server endpoint port (default `51820`) |

### Cloudflare WARP

Cloudflare WARP is not a named Gluetun provider — use the `custom` WireGuard
mode with keys generated by a WARP client/tool:

```dotenv
VPN_SERVICE_PROVIDER=custom
VPN_TYPE=wireguard
WIREGUARD_PRIVATE_KEY=<warp-private-key>
WIREGUARD_ADDRESSES=<warp-address>/32
WIREGUARD_PUBLIC_KEY=<warp-public-key>
WIREGUARD_ENDPOINT_IP=engage.cloudflareclient.com
WIREGUARD_ENDPOINT_PORT=2408
```

For a commercial VPN, set the provider-specific variables instead (for example
`VPN_SERVICE_PROVIDER=mullvad`). See the [Gluetun wiki](https://github.com/qdm12/gluetun-wiki).

> **Note:** TorrServer keeps its data and settings across VPN toggles; only the
> network path changes. Stop the stack before switching profiles.

## 🔌 Use with the Jellyfin plugin

1. Install [TorrServer STRM Manager](https://github.com/fryt3ch/Jellyfin-TorrServerStrm-Plugin).
2. In the plugin settings set **TorrServer URL** to `http://torrserver:8090`.
3. If clients cannot reach TorrServer directly, enable
   **"Force transcoding of remote media sources"** for those users so Jellyfin
   proxies the stream.

The plugin rewrites existing `.strm` files when the URL changes, so you can move
between the direct and VPN setups without re-importing media.

## 📂 Volumes and paths

| Variable | Default | Purpose |
| --- | --- | --- |
| `JELLYFIN_CONFIG` | `./data/jellyfin/config` | Jellyfin config/cache |
| `DOWNLOADS_PATH` | `./data/downloads` | Media path mounted at `/mnt/downloads` |
| `TORRSERVER_DATA` | `./data/torrserver` | TorrServer config/database |
| `GLUETUN_DATA` | `./data/gluetun` | Gluetun state |

`data/` and `.env` are git-ignored.
