# 🎬 Jellyfin + TorrServer (optional VPN)

**A ready-to-run Docker Compose stack that pairs Jellyfin with TorrServer, with an optional Gluetun VPN profile for regions with strict torrenting laws.**

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

- 🐳 **One command** to start Jellyfin + TorrServer.
- 🔌 **Drop-in** with the [TorrServer STRM Manager](https://github.com/fryt3ch/Jellyfin-TorrServerStrm-Plugin) Jellyfin plugin.
- 🛡️ **Optional VPN** (Gluetun, WireGuard — including Cloudflare WARP) that routes TorrServer traffic only.
- ⚙️ **Configurable** paths, UID/GID, timezone, and bind address via `.env`.

---

## 📋 Requirements

- Docker Engine + **Docker Compose v2.24+** (the VPN overlay uses the `!reset` tag).
- A downloads/media path that Jellyfin can read.
- Optional: the [TorrServer STRM Manager](https://github.com/fryt3ch/Jellyfin-TorrServerStrm-Plugin) plugin to import magnets as `.strm` files.

---

## 🚀 Quick start (no VPN)

```bash
# 1. Create the shared network used by Jellyfin and TorrServer
docker network create jellyfin-net

# 2. Configure
cp .env.example .env
# edit .env: PUID/PGID, TZ, DOWNLOADS_PATH, ...

# 3. Start
docker compose up -d
```

Jellyfin is reachable from other containers on `jellyfin-net` as `http://jellyfin:8096`.
TorrServer is reachable as `http://torrserver:8090`.

If you are **not** behind a reverse proxy and want direct access, uncomment the
`ports` entries in `docker-compose.yml` (or use `docker-compose.override.example.yml`).

## 🛡️ Enable the VPN profile (strict regions)

The VPN overlay moves TorrServer into a Gluetun network namespace so **all**
TorrServer traffic goes through the VPN. Jellyfin is unaffected and still
reaches TorrServer as `http://torrserver:8090`.

1. Fill in the `WIREGUARD_*` values in `.env` (see below).
2. Start with the `vpn` profile:

```bash
docker compose --profile vpn \
  -f docker-compose.yml -f docker-compose.vpn.yml up -d
```

### WireGuard values

Gluetun's `custom` provider needs:

| Variable | Meaning |
| --- | --- |
| `WIREGUARD_PRIVATE_KEY` | Client private key |
| `WIREGUARD_ADDRESSES` | Client address, e.g. `10.2.0.2/32` |
| `WIREGUARD_PUBLIC_KEY` | Server public key |
| `WIREGUARD_ENDPOINT_IP` | Server endpoint **IPv4 address** (hostnames are not supported) |
| `WIREGUARD_ENDPOINT_PORT` | Server endpoint port (default `51820`) |
| `WIREGUARD_PERSISTENT_KEEPALIVE_INTERVAL` | Optional; keeps NAT mappings alive, e.g. `25s` |

### Cloudflare WARP

Cloudflare WARP is not a named Gluetun provider — it uses the `custom`
WireGuard mode with a profile generated by a tool. The de-facto tool is
[`wgcf`](https://github.com/ViRb3/wgcf) by ViRb3.

#### 1. Generate a WARP WireGuard profile

Download the `wgcf` binary for your platform from the
[releases page](https://github.com/ViRb3/wgcf/releases), then run:

```bash
wgcf register     # creates wgcf-account.toml
wgcf generate     # creates wgcf-profile.conf
```

You can optionally add a keepalive with `wgcf generate --keepalive`.

`wgcf-profile.conf` looks like this (values redacted):

```ini
[Interface]
PrivateKey = <client-private-key>
Address = 172.16.0.2/32
MTU = 1280

[Peer]
PublicKey = <server-public-key>
AllowedIPs = 0.0.0.0/0, ::/0
Endpoint = engage.cloudflareclient.com:2408
```

#### 2. Map the profile into `.env`

| `wgcf-profile.conf` | `.env` variable |
| --- | --- |
| `[Interface]` → `PrivateKey` | `WIREGUARD_PRIVATE_KEY` |
| `[Interface]` → `Address` (IPv4 only) | `WIREGUARD_ADDRESSES` |
| `[Interface]` → `MTU` | `WIREGUARD_MTU` (`1280`) |
| `[Peer]` → `PublicKey` | `WIREGUARD_PUBLIC_KEY` |
| `[Peer]` → `Endpoint` host | `WIREGUARD_ENDPOINT_IP` (must be an IPv4) |
| `[Peer]` → `Endpoint` port | `WIREGUARD_ENDPOINT_PORT` (`2408`) |

Resulting `.env`:

```dotenv
VPN_SERVICE_PROVIDER=custom
VPN_TYPE=wireguard
WIREGUARD_PRIVATE_KEY=<client-private-key>
WIREGUARD_ADDRESSES=172.16.0.2/32
WIREGUARD_MTU=1280
WIREGUARD_PUBLIC_KEY=<server-public-key>
WIREGUARD_ENDPOINT_IP=162.159.192.1
WIREGUARD_ENDPOINT_PORT=2408
WIREGUARD_PERSISTENT_KEEPALIVE_INTERVAL=25s
```

> **The endpoint must be an IP.** Gluetun does not accept hostnames for
> `WIREGUARD_ENDPOINT_IP`
> ([gluetun#2680](https://github.com/qdm12/gluetun/issues/2680)).
> `162.159.192.1` is a WARP endpoint that `engage.cloudflareclient.com` resolves
> to. If it does not connect, resolve the hostname yourself
> (`nslookup engage.cloudflareclient.com`, or `getent hosts ...` on Linux/macOS)
> and try another IPv4 in the `162.159.192.0/24` range.

> **Alternative:** drop the generated `wgcf-profile.conf` at
> `${GLUETUN_DATA}/wireguard/wg0.conf` (for example
> `./data/gluetun/wireguard/wg0.conf`). Gluetun reads it, and file values take
> precedence over environment variables. See the
> [Gluetun WireGuard options](https://github.com/qdm12/gluetun-wiki/blob/main/setup/options/wireguard.md).

#### 3. Verify the tunnel

```bash
docker compose --profile vpn \
  -f docker-compose.yml -f docker-compose.vpn.yml up -d

docker compose --profile vpn \
  -f docker-compose.yml -f docker-compose.vpn.yml \
  exec gluetun wget -qO- https://1.1.1.1/cdn-cgi/trace | grep warp
```

The output should contain `warp=on`.

> ⚠️ **WARP is not a torrent VPN.** Cloudflare WARP is a consumer privacy proxy,
> not a P2P/VPN service. Torrent traffic may be throttled or blocked, and using
> it for P2P can violate Cloudflare's terms. It is a lightweight option for
> bypassing regional blocks — for real torrent privacy use a commercial VPN
> provider via Gluetun instead.

For a commercial VPN, set the provider-specific variables instead (for example
`VPN_SERVICE_PROVIDER=mullvad`). See the [Gluetun wiki](https://github.com/qdm12/gluetun-wiki).

**References:** [ViRb3/wgcf](https://github.com/ViRb3/wgcf) ·
[Gluetun custom provider](https://github.com/qdm12/gluetun-wiki/blob/main/setup/providers/custom.md) ·
[Gluetun WireGuard options](https://github.com/qdm12/gluetun-wiki/blob/main/setup/options/wireguard.md) ·
[Cloudflare WARP](https://developers.cloudflare.com/warp-client/)

> **Note:** TorrServer keeps its data and settings across VPN toggles; only the
> network path changes. Stop the stack before switching profiles.

## 🔌 Use with the Jellyfin plugin

1. Install [TorrServer STRM Manager](https://github.com/fryt3ch/Jellyfin-TorrServerStrm-Plugin).
2. In the plugin settings set **TorrServer URL** to `http://torrserver:8090`.
3. If clients cannot reach TorrServer directly, enable
   **"Force transcoding of remote media sources"** for those users so Jellyfin
   proxies the stream.

The plugin rewrites existing `.strm` files when the URL changes, so you can move
between the direct and VPN setups without re-importing media.

## 📂 Volumes and paths

| Variable | Default | Purpose |
| --- | --- | --- |
| `JELLYFIN_CONFIG` | `./data/jellyfin/config` | Jellyfin config/cache |
| `DOWNLOADS_PATH` | `./data/downloads` | Media path mounted at `/mnt/downloads` |
| `TORRSERVER_DATA` | `./data/torrserver` | TorrServer config/database |
| `GLUETUN_DATA` | `./data/gluetun` | Gluetun state |

`data/` and `.env` are git-ignored.
